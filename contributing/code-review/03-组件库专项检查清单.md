## §A 静默失效类 🔴（本库头号风险）

> 特征：**不报错、不告警**，只是样式/事件实际没生效。Web 预览和单测都可能全绿。

### A1. 内联样式必须是对象语法（§19）

字符串 `:style` 会被 `patchProp` **静默替换为 `{}`**。

```vue
<!-- ❌ 样式全部消失，无任何提示 -->
<view :style="`height: ${itemHeight}px`">
<view :style="'top: 1px; left: 2px'">
<view custom-style="color: red">

<!-- ✅ -->
<view :style="{ height: addUnit(itemHeight) }">
<view :style="parseStyle(customStyle)">
<view :style="filterStyle({ top: y, left: x })">
```

- [ ] 模板内所有 `:style` 均为对象/数组语法
- [ ] 消费方传入的 `customStyle` 已过 `parseStyle()` 归一
- [ ] 未使用 `objToStyle()` 拼字符串后下发（§19.3 明确禁止）
- [ ] 多段样式合并用 `{ ...rootStyle, ...parseStyle(customStyle) }` 而非字符串拼接
- [ ] 已确认 `test/inline-style-regression.test.ts` 与 `layout-inline-style-regression.test.ts` 全绿

> **历史故障**：`wd-picker-view` 列不滚动、`wd-config-provider` 主题整体失效、`wd-progress` 宽度失效、`wd-qr-code` 尺寸失效 —— 全部由字符串样式引起。

### A2. 类名必须与 CSS 选择器一致（§5.5）

`m(size)` 生成 `.wd-xxx--size`，`when(size)` 生成 `.wd-xxx.is-size`。
**任一方写错都不报错**，CSS 规则不匹配，整组声明（height / padding / font-size / background）被静默丢弃。

```scss
// ❌ DOM 推的是 is-medium，这里却生成 --medium → 按钮塌成内容高度
@include m(medium) { height: 44px; padding: 0 16px; }

// ✅ 与 DOM 推送的类名形式一致
@include when(medium) { height: 44px; padding: 0 16px; }
```

- [ ] 新增/修改状态类时，已确认 **DOM 实际推送的类名形式**（`is-${x}` 还是 `--${x}`）再选 mixin
- [ ] 嵌套写法（如 `when(icon)` 内的 `&.is-mini`）与外层尺寸类**同源**
- [ ] **已执行验证**：`pnpm build:css` 后 grep 生成的 `index.css`，确认选择器与模板类名一致

```bash
# 推荐的验证命令（作者应在 PR 中附上输出）
pnpm build:css
grep -o '\.wd-button\.[a-z-]*' packages/ui/src/components/wd-button/index.css | sort -u
# 与 wd-button.vue 中推送的类名逐一比对
```

> **历史故障**：`wd-button` 尺寸类全部丢失高度与内边距 —— 正是此 bug。

### A3. `flex-shrink` 默认值为 1（§19 附带陷阱）

定高且不允许压缩的 flex 子项必须显式 `flex-shrink: 0`，否则会被容器按比例压缩（行高塌成 1/4）。

- [ ] 定高的 flex 子项已加 `flex-shrink: 0`
- [ ] 内容总高可能超出容器高度的场景已检查

### A4. Web 预览不遵循 z-index（§19 附带陷阱）

不透明底色的 `position: absolute` 装饰元素若排在兄弟节点**之前**，会连文字一起盖掉（Web 按 DOM 逆序绘制，真机按 z-index）。

- [ ] 此类装饰元素（如选中指示带）排在内容节点**之后**
- [ ] 且 z-index 低于内容节点

## §B 真机崩溃类 🔴（Web 全绿但真机白屏）

### B1. SVG content 元素白名单（§8）

`<svg :content>` **只支持**：`svg` / `g` / `path` / `rect` / `circle` / `polyline`。

白名单外元素会导致真机 `RuntimeException: Insertion (new) failed due to unknown child signature`（Lynx 错误码 **9902**），**属致命异常且 JS 侧无法捕获**。

- [ ] SVG content 中无 `defs` / `linearGradient` / `radialGradient` / `stop` / `clipPath` / `image` / `text` / `use`
- [ ] 渐变已降级为纯色（取首个色标），或走 data URI 导出路径
- [ ] 图片用原生 `<image>` 叠加，未内嵌进 svg content
- [ ] 渲染路径已过 `sanitizeSvgContent()` 安全网
- [ ] 新增组件生成 SVG 时只用白名单元素

### B2. 禁止 Main Thread Script（§10）

- [ ] 无 `main-thread-bind*` 事件绑定
- [ ] 无 `useMainThreadRef` / `runOnMainThread` / `lynxWorkletImpl`
- [ ] 高频交互组件状态在后台线程 `ref`，样式经 computed 输出（参照 `wd-slider` 的 `lineStyle`）
- [ ] 已确认 `test/no-main-thread-script.test.ts` 全绿

> **理由**：可用性检测在后台线程恒为 `undefined`，MTS 绑定永不生效；且跨线程注水有时序竞争，生产构建会崩。

### B3. 事件注册表的数组陷阱（§14）

vue-lynx 把事件处理器按 sign 存进注册表，**只容忍 `null`/`undefined`**。存入数组（`mergeProps` 合并同名监听产生）→ 真机 `TypeError: _getRegistryState_handlers_get is not a function`。

- [ ] **未**给包裹层组件补绑 `@touchmove="noop"`（锁滚走 `:lock-scroll` → `disable-touch-move` 链路）
- [ ] 给**组件**绑的事件名已在其 `defineEmits` 中声明
- [ ] 交互组件根 view 的原生事件名已同时声明为 emit 并在自有处理器中转发
- [ ] `wd-transition` 家族根链已按同法处理
- [ ] 四份事件回归测试全绿：`event-tap-registry` / `event-merge-props` / `event-registry-all-components` / `overlay-tap-regression`

### B4. `@click` 在 Lynx 是死事件（§14，2026-10-16 订正）

Lynx view **只派发 `tap`**（`bindtap`）。`@click` 绑在裸 view 上 → 交互全端失效（如遮罩常驻关不掉）。

- [ ] 裸 view 上**无** `@click`，一律用 `@tap`
- [ ] `WdOverlay` 的 `click` / `tap` 双轨 emit 保持 wot-ui API 对齐
- [ ] 已知待修点已处理：pagination / fab / form-item / image-preview 关闭按钮 / video-preview 关闭按钮 / swipe-action 选项按钮
- [ ] 关闭行为断言使用 `fireEvent.tap`，**未使用** `fireEvent.click`（后者会合成事件造成假绿）

### B5. 父子通信的响应式陷阱（§13）

父组件在渲染路径读子组件 props 时，对象/数组类型 props 会触发无限递归更新：`Maximum recursive updates exceeded`。

- [ ] 父组件读子组件 props 一律走 `toRaw` 非跟踪读取

```ts
import { toRaw } from 'vue-lynx'

function rawChildProps(child: any): Record<string, any> {
  const props = child && child.$.props
  return (props && toRaw(props)) || {}
}
```

- [ ] `child.$.exposed!` 这类非空断言在渲染路径 / Promise 回调中已先判空

## §C 布局类 🔴（Lynx 3.x linear 默认布局）

### C1. `display: flex` 必须显式声明（§15）

当前工具链 `default_display_linear: true` —— view 默认是 **linear 布局**，不是 web 意义上的 flex 容器。

- [ ] 任何依赖**横向排列**的容器显式写了 `display: flex`
- [ ] `flex-direction` / `flex-wrap` / `flex-grow` 均挂在 `display: flex` 的元素上
- [ ] 由 `inline-flex` 改写而来的容器补了 `flex-direction: row`
- [ ] 组件根 `display: inline-flex` → `display: flex`

```scss
/* ❌ 声明被静默丢弃，元素纵向逐行排列（"一行一个、还没间距"） */
.row { flex-direction: row; }

/* ✅ */
.row { display: flex; flex-direction: row; }
```

> **验证手段**：`rspeedy dev` 起服务后访问
> `http://localhost:3001/__web_preview?casename=<bundle>` 截图核对。

### C2. `inline-flex` / `inline-block` 不被识别（§5.4 / §15）

引擎只认 `flex` / `none` / `linear`。

- [ ] 无 `display: inline-flex`
- [ ] 无 `display: inline-block`

### C3. 无 `::before` / `::after`（§5.4）

- [ ] 无伪元素；需要时改用**模板中的真实元素 + 对应类名**（如 `__bar`、`__hairline`）

### C4. 其他 Lynx 不支持的 CSS（§5.4）

- [ ] 无 `:nth-child()` / `:first-child` / `:last-child`（改用 `v-for` 索引生成类名或内联样式）
- [ ] 无 `conic-gradient` / `-webkit-line-clamp` / `-webkit-box`
- [ ] 无 `!important`
- [ ] 无 `:deep(...)` / `::v-deep`
- [ ] **无 `box-shadow`**（§3：Lynx 各端表现不一致，层级靠表面色 + `--wd-border-1/2` 描边表达）

### C5. 多行省略需模板配合（§5.6）

- [ ] CSS 保留 `overflow:hidden; text-overflow:ellipsis`
- [ ] 模板同步给 `<text>` 加 `text-maxline="N"`

## §D 性能红线 🟠

### D1. `touchmove` 热路径禁止 `getRect`（§16）

`getRect` 是经 `createSelectorQuery` 的**异步跨线程节点查询**，在 `touchmove` 里调用 = 每帧两次线程间往返。

- [ ] 宽度/位置为**一次性度量 + 缓存**（挂载后或尺寸相关 props 变化时）
- [ ] `touchmove` 热路径只读缓存
- [ ] 参照合规实现：`wd-slider`（`initSlider`）、`wd-fab`（拖动开始时测一次）、`wd-tabs`

### D2. 按压缩态用 `:active` 而非 JS（§1.3 / §17）

- [ ] 可点击元素按压态用 CSS `:active` + 对应类名样式
- [ ] **未**用 touch 事件 + JS state 实现按压
- [ ] 禁用态、加载态不响应按压已用特异性覆盖

### D3. 能用 CSS 解决的不用 JS（§1.3）

- [ ] 位移动画用 CSS `transition`（跟手时 `transition: none`，落位时恢复）
- [ ] 未在 render 路径中创建新对象/函数导致子组件重渲染

## §E 规范符合性 🟠

### E1. `.vue` 文件结构（§4）

```vue
/*
 * wd-xxx — 组件中文名
 *
 * Lynx 实现说明：（如有适配点逐条说明；没有则省略本块）
 */
<script lang="ts" setup>
import './index.css'          // 必须在第一行

import { computed, ref } from 'vue-lynx'   // 一律 vue-lynx，禁止 'vue'
import { xxxProps } from './types'

defineProps(xxxProps)
</script>

<template>
  <!-- 所有文本必须在 <text> 中 -->
</template>
```

- [ ] import 来源一律 `'vue-lynx'`（**无** `from 'vue'`）
- [ ] `import './index.css'` 在 `<script setup>` 第一行
- [ ] **无 `<style>` 块**
- [ ] 无 `<script>` options 块
- [ ] **顶层注释中无 `<view>` / `<svg>` 等标签形式**（Vue 解析器会识别为自定义块导致编译失败）→ 写成 "view 元素"
- [ ] `<view>` 内所有裸文本（含 `{{ }}` 插值）均包裹在 `<text>` 中
- [ ] 模板内组件用 **PascalCase**（`<WdButton>`），kebab-case 会被判为原生元素
- [ ] 无 uni-app 条件编译残留（`// #ifdef` / `// #ifndef` / `// #endif`）

### E2. 样式令牌（§3 / §5）

- [ ] 只消费 `--wd-*` 令牌，**无** `--wot-*` 残留
- [ ] 组件私有令牌定义在 `index.scss` 头部，回退到语义令牌：
      `$button-primary-bg: var(--wd-button-primary-bg, var(--wd-color-primary)) !default;`
- [ ] 语义令牌优先于原始刻度（`--wd-color-primary` 优于 `--wd-blue-6`）
- [ ] 品牌色 `--wd-purple-6`（#7F5CFF）**未改动**（既定品牌色，不随设计刷新更改）
- [ ] 动效使用 `--wd-duration-*` + `--wd-ease-*`，未硬编码时长/缓动
- [ ] 对比度达标（警告底文字用 `--wd-color-on-warning`，对比度 ≥ 4.5:1）

### E3. 依赖方向（§7）

- [ ] `common/` 与 `composables/` **未 import 组件目录**
- [ ] 共享契约（cell-group / form / config-provider 的 provide 类型与 key）定义在 composable 层
- [ ] 通用能力优先用成熟方案（dayjs、`vue-lynx` 内置 Transition），未自研通用逻辑（§1.6）

### E4. 生成物（§2）

- [ ] **未手改 `index.css`**（只改 `index.scss`，由 `build:css` 生成）
