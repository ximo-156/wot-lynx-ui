# ADR-002 分阶段拆包

- **状态**：已采纳
- **日期**：2026-10-16
- **相关**：ADR-003、ADR-012

## 背景

单包 `wot-lynx-ui` 承载全部能力。拆包能带来独立版本、独立发布、团队并行、能力复用，但一次性全拆的迁移风险极高（import 路径全变、循环依赖暴露、CI 全红）。

## 决策

**分阶段拆，每阶段独立可交付、可回滚**，顺序为「收益/成本比」从高到低：

1. `tokens`（设计系统，复用面最广）
2. `runtime`（骨架能力，非组件库也能用）
3. `composables`
4. `icons`（资产包，避免组件包体积膨胀）
5. `locale`（社区可独立贡献）

全程保留 `wot-lynx-ui` 兼容层（re-export 全部），存量用户零改动。

## 后果

- 每拆一个包，就多一份 `package.json` / 构建配置 / 版本号的维护成本。
- 兼容层会长期存在，增加一层间接。

## 推翻条件

- 拆分后出现跨包循环依赖 → 说明拆包时机过早，应回退并先做 ADR-012 的横向收敛。
