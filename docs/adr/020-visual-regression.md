# ADR-020 视觉回归拍组件区域而非整页，基线按平台隔离

- **状态**：已采纳
- **日期**：2026-10-23
- **相关**：`scripts/visual-regression.mjs`、`scripts/lib/png.mjs`、`scripts/lib/image-diff.mjs`、`scripts/lib/chrome.mjs`、`visual/targets.json`、`visual/baseline/<platform>/`、`packages/ui/test/png-codec.test.ts`、`packages/ui/test/visual-diff.test.ts`、`package.json`（`visual:baseline` / `visual:check`）
- **依赖**：ADR-017（`meta.json`）、ADR-018（文档站）

## 背景

PR 模板里有一条人工项：「涉及布局改动，已用 `__web_preview` 截图核对」。架构评审
把它记为 P2 问题「无视觉回归：截图靠人工核对」。

这个项目最典型的样式缺陷是**整块声明静默失效**：SCSS 里 `m()` 与 `when()` 用错
（生成 `.wd-x--small` 而 DOM 推的是 `is-small`）、`index.css` 没重新编译、类名改了
但模板没跟着改。这几种在截图里表现为「组件突然没样式了」，人眼一瞥就能发现——
所以截图核对一直有效，问题只在于「靠人记得做」。

落地时有三个约束是硬的：

| 约束 | 影响 |
|---|---|
| 无头 Chrome 可用，但没有 playwright / puppeteer | 只能走 CDP 或命令行截图，且不能引入依赖 |
| 组件页正文由 `meta.json` 生成 | 整页截图会把「改了一句 JSDoc」变成 106 张基线全红 |
| 字体光栅化跨平台不同 | 一份基线跨平台比较必然全红，那不是回归 |

## 决策

### 1. 拍组件区域，不拍整页

目标是文档站组件页右侧栏的 H5 预览（`.wd-h5-phone__screen`）——用真实组件源码
渲染出来的手机屏。

不拍整页的原因很实际：`gen-docs` 生成的 Props/Events 表格占据页面主体，任何一次
契约描述修订都会让全部基线失效。裁剪到组件区域后，基线只随**样式与组件行为**变化。
这也顺带把导航栏、侧边栏、页脚全部排除在外。

裁剪需要 CDP 的 `Page.captureScreenshot` + `clip`，命令行 `--screenshot` 做不到，
所以用 WebSocket 直连调试端口（Node 22 内建 `WebSocket`，零依赖）。

### 2. 基线按平台分目录，缺基线明确跳过

`visual/baseline/<platform>/<slug>.png`。Windows / macOS / Linux 的字体渲染不同，
中文字形差异尤其大，一份基线不可能跨平台通用。

**缺基线时报「跳过」，不报「通过」**：假装通过比跳过糟得多。全新 clone 或换平台
之后先跑一次 `--update`。

### 3. 零依赖 PNG 编解码

只需要「读截图 → 比像素 → 写差异图」。PNG 规范足够小：位深 8、非隔行、
colorType 2/6、滤波 0–4 全部支持，`node:zlib` 负责 inflate/deflate，CRC32 自带表。

装 `sharp` 要下载原生包、`pngjs` 是纯 JS 但把开发期工具变成依赖——都不划算。
不支持的输入一律抛错，不猜：静默产出错误像素会让视觉回归的结论失去意义。

### 4. 冻结动画与过渡

注入 `animation:none; transition:none`。不冻结的话，同一页两次截图会因动画相位
不同而必然产生差异，工具就退化成随机噪声。

代价要写清楚：基线记录的是**静止态**，动效本身不在覆盖范围内。

### 5. 页面清单从 meta 派生

`visual/targets.json` 只放参数与排除项，组件列表由 `packages/ui/meta.json` 推导
（`wd-button` → `button` → `/components/button.html`）。项目已经因为「手写第二份
清单」出过两次问题（barrel、文档侧边栏），视觉回归不该成为第三份。

### 6. 空白基线要显式报告

有些组件在预览里默认什么都不渲染：浮层要点击才出现、子组件必须有父级、没有手工
演示只走了兜底页。它们截出来是一整片背景色，**基线永远不会回归**。

如果只报「106 张基线全部通过」，会给人一种「覆盖很全」的错觉。所以捕获后检查
内容区（裁掉四角，避开手机屏圆角）的颜色数，纯色即判空白，单独列出来并说明
「这些基线不会误报，但也拦不住回归」。

### 7. 不稳定的组件用证据排除，且必须写理由

时间相关的东西不能做视觉回归：`count-to` 的数字滚动由 JS 计时器驱动（CSS 冻结
无效），`datetime-picker-view` 显示当前时间。这类组件每次运行都会误报。

`--stability` 模式连拍两次、报告差异，用**证据**而不是直觉决定排除名单。
`exclude` 的每一项都必须写 `reason`，缺了直接报错——排除等于放弃覆盖，理由要留在
数据里（同 ADR-013 对 `families.json` 的要求）。

### 8. 不进 CI 阻塞

平台基线决定了：CI 跑在 Linux 上，而基线是开发机生成的，直接比较必然全红。

所以当前定位是**开发机上的机器检查**，替代 PR 清单里那条人工项。CI 化的正解是
「同一容器内分别拍 base 与 head 再比」，不依赖预置基线——见「推翻条件」。

## 后果

### 实测

| 项目 | 结果 |
|---|---|
| 全量生成基线 | 106 张 / 85 秒（约 0.8 秒每页，单浏览器实例复用） |
| 全量复检 | 104 张全部 0.000% |
| 基线体积 | 944 KB（104 张，单张 1.7–17 KB） |
| 截图确定性 | 同一页连拍 3 次，PNG **字节级一致**；跨进程、跨端口复检仍 0.000% |
| 空白基线 | 16 个（checkbox / count-to / coupon / loadmore / navbar-capsule / notify / overlay / pull-refresh / radio / root-portal / share-sheet / sort-button / sticky / sticky-box / swiper-nav / transition） |
| 不稳定组件 | 2 个（`count-to` 连拍差异 0.23%；`datetime-picker-view` 某次复检出现 19×264 竖向差异带） |
| 全量稳定性扫描（排除 2 个之后） | 104 个全部稳定，0 个不确定 |

### 负向验证

把 `--wot-brand-6` 从 `#755FFEFF` 改成品红 `#FF00AAFF`（一处 token），复检结果：

| 组件 | 变化占比 | 说明 |
|---|---|---|
| `button` | 11.94% | 主色按钮全部变色 |
| `tag` | 3.88% | 部分标签使用主色 |
| `cell` | 0.000% | 不使用主色，正确地未报 |

差异图把变化像素涂红、未变区域压成灰阶，人一眼能定位到哪一块动了。

### 两次「负向验证没生效」的记录

1. **第一次改的是不生效的那批颜色**。CSS 里同时存在小写 `#755ffe`（103 处）与
   大写 `#755FFEFF`（1 处，真正的 `--wot-brand-6` 令牌）。替换了小写那批，复检
   0.000%——差点误判成「工具抓不到颜色变化」。用 CDP 读 `getComputedStyle` 才定位到
   真正生效的值。**又一次「改到的不是执行的那条路径」**。
2. **首版没有空白检测**。106 张基线全部「成功」，直到按体积排序发现最小的几张
   只有 1.7 KB，打开一看是纯色。工具本身没报错，是人工看产物才发现的。

### 已知限制

- **只覆盖静止态**：动画、过渡、以及任何 JS 计时器驱动的变化都拍不到。
- **只拍可视区**：手机屏内容超出时只截第一屏，滚动区域内的回归不会被发现。
- **基线跟平台绑定**：换平台或换字体要重新 `--update`。
- **空白组件等于没覆盖**：16 个组件的基线只能发现「突然渲染出东西」，发现不了样式错误。
- **未接入 CI**：见决策 8。

## 推翻条件

- CI 若引入固定容器镜像，可把基线改为在镜像内生成并提交，此时「缺基线」不再发生，
  本 ADR 决策 8 作废。
- 更彻底的做法是**同一容器内拍 base 与 head 再比**：checkout 基准 commit → 构建 →
  拍一组；再拍当前 → 比。完全不依赖预置基线，且天然跨平台一致。成本是两次构建，
  可按 `api-diff` 或 `git diff` 圈定的改动组件做增量。
- 若空白组件的演示补齐（浮层给一个默认展开的静态态），决策 6 的覆盖缺口会自然收窄。
