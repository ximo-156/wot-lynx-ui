# ADR-003 组件域包暂不拆

- **状态**：已采纳（前提修正于 2026-10-22）
- **日期**：2026-10-16 ／ 修订：2026-10-22
- **相关**：ADR-012、`ARCHITECTURE.md §3.2`

## 背景

按域拆组件包（`components-form` / `components-display` / `components-feedback` …）是常见做法。v1.0 的判断是「101 个组件规模下，拆域带来的版本管理成本 > 收益」，触发条件写为「单域 > 40 组件或单域 > 3 人」。

## 决策

**暂不拆域包。** 但 v1.0 给出的理由**是错的**，2026-10-22 依赖图实测后修正：

> 拆域包的真实障碍**不是版本管理成本，而是依赖图不是 DAG**。
>
> - `wd-address-edit`（form 域）依赖 `wd-cell`（display 域）、`wd-button`（basic 域）
> - `wd-action-sheet`（feedback 域）依赖 `wd-popup`（display 域）
> - 全库 153 条跨组件边、5 个循环依赖
>
> 按域切分后，包依赖图会**立刻出现环**。这不是「暂不做」，是**做不了**。

因此触发条件从「单域 > 40 组件」改为**依赖图门槛**：

```
业务 ↔ 业务 依赖边 ≤ 60 且 环 = 0
```

达成手段不是拆包（拆包不改变依赖图，只改变它的可见性），而是 ADR-012 的 Primitives 层收敛。

## 后果

- 组件包保持整包，`import { WdButton }` 的 tree-shaking 依赖 `sideEffects` 正确配置（ADR-007）。
- 团队并行依赖 CODEOWNERS 按域划分，而非物理分包。

## 推翻条件

- `业务↔业务边 ≤ 60 且环 = 0` 达成 → 可启动域包拆分评估。
- 出现「某域被独立产品复用」的明确需求 → 优先拆该域，而非全量按域拆。
