## 0. 五条不可协商的原则

1. **令牌只走单向**：组件 → 语义 → 原始刻度。组件里出现字面量（`#fff` / `12px` / `500`）即为缺陷，
   除非它是某个令牌的**声明处**回退值。
2. **视觉尺寸 ≠ 命中区**。视觉 40px 的按钮，命中区必须 ≥ 44px（外扩，不是拉高）。
   把视觉尺寸直接拉到 44 会让密度失控——这是两种不同的约束，不能互相顶替。
   **唯一的成体系例外是键盘**（见 §10.1）：密集已知目标 + 键高补偿，允许单键宽 < 44。
3. **层级靠表面色 + 描边，不靠阴影**。Lynx 各端 `box-shadow` 表现不一致
   （`review-lint` 的 `scss/no-box-shadow` 是 error 级）。阴影只能作为**可选增强**，
   且必须走令牌；删掉阴影后层级仍须成立。
4. **每个可交互元素必须有四态**：默认 / 按压 / 禁用 / 焦点。缺一个就不算完成。
5. **尺度是有限的**。尺寸、字号、圆角、间距、时长各自只能取阶梯上的值。
   阶梯外的值（15px、13px、0.15s）一律视为一次性决定，需要单独说明理由。

## 1. 尺寸阶梯（缺失最严重的一环）

现状：控件高度散落在 `$n-28 / 32 / 36 / 40 / 44 / 48 / 50` 七个值上，没有命名、没有用途绑定。
后果是同类控件高度不一致（按钮 40、搜索框 36、输入框 28），拼在一起像不同产品。

**规范：控件高度只允许取阶梯值，并按用途绑定。**

| 档位 | 视觉高度 | 命中区 | 用途 | 现状对应 |
| --- | --- | --- | --- | --- |
| `size-2xs` | 24 | 44（外扩） | 徽标、清除图标容器 | badge |
| `size-xs` | 28 | 44（外扩） | 迷你按钮、步进器 | button-mini / input-number |
| `size-sm` | 32 | 44（外扩） | 小按钮、胶囊、标签大号 | button-small / navbar-capsule |
| `size-md` | 36 | 44（外扩） | 搜索框、紧凑输入 | search |
| `size-lg` | 40 | 44（外扩） | **默认按钮、默认输入** | button-medium |
| `size-xl` | 44 | 44 | 大按钮、导航栏 | button-large / navbar |
| `size-2xl` | 48 | 48 | 键盘键、列表主行 | keyboard key |
| `size-3xl` | 56 | 56 | 底部标签栏、主行动区 | tabbar |

命中区补偿的两种实现（二选一，不许第三种）：

- 外层容器 `min-height: 44px` + `align-items: center`（推荐，布局可预测）；
- 命中区伪元素外扩——Lynx 无伪元素，**不可用**，因此只能选第一种。

> 新增控件若落在两档之间，**改用途，不改阶梯**。阶梯加档要写 ADR。

## 2. 间距与网格

- **基准网格 4pt**。允许值：4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 / 40 / 48。
- 例外：`--wot-padding-main` = **10px 不在 4pt 网格上**。它是历史主间距，
  导致「12 与 10 混用」无法判断谁更"标准"。
  **新代码禁止使用 `padding-main` / `spacing-main`**，改用 `-tight`(8) 或 `-loose`(12)。
  存量按 P2 迁移，不在本次批量改。
- 同一容器内间距只允许**一种步长**。卡片内 8，卡片间 12，区块间 24——不要卡片内 6/10/12 混排。

## 3. 字阶

### 3.1 现状问题

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| 命名倒置 | `body-size-extra-large`=16 < `super-large`=17 < `ultra-large`=18 | 「extra」直觉上最小，实际在中间 |
| 离群档位 | body 15 / 17；label 9 | 15/17 不在任何常见字阶上；9px 低于可读下限 |
| 行高不成比例 | 14/20(1.43)、15/22(1.47)、16/24(1.5)、17/24(1.41) | 同段落换档位，行距会跳 |
| 字阶外字号 | `pull-refresh` 13px、`coupon` 11px 与 24px | 逐组件自造字号 |

### 3.2 规范

**字号只允许**：11 / 12 / 14 / 16 / 18 / 20 / 24 / 28 / 32。

- **11px 是可读下限**。9 / 10px 仅允许用于徽标数字，且不得承载语义信息。
- 15 / 17 标记为 `deprecated`，新代码禁用，存量随 P2 迁移到 14 / 16 / 18。
- 行高按**比例**绑定，不按绝对值：

| 字号 | 行高 | 比例 | 用途 |
| --- | --- | --- | --- |
| 11 | 16 | 1.45 | 辅助标签 |
| 12 | 18 | 1.50 | 标签、说明 |
| 14 | 20 | 1.43 | **正文默认** |
| 16 | 24 | 1.50 | 正文强调 |
| 18 | 26 | 1.44 | 小标题 |
| 20 | 28 | 1.40 | 标题 |
| 24 | 32 | 1.33 | 大标题、金额 |
| 32 | 40 | 1.25 | 展示型数字 |

> 24px 的行高现状是 34（1.42），与 18px 的行高 26 不成体系。数字键盘 24px 字号建议用 32 行高。

## 4. 字重

现状：`100/200/300/400/600/700/700`——**没有 500，且 semibold 与 bold 同值**，
而实际代码里有 6 处写了 `500`（coupon ×3、submit-bar ×2、share-sheet ×1）。
这意味着这 6 处字重在换字体后会落到浏览器最近邻（400 或 600），观感不可控。

**规范：字重只允许四档，语义命名取代数字命名。**

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `font-weight-regular` | 400 | 正文、标签 |
| `font-weight-medium` | **500** | 强调、按钮文字、金额前缀 |
| `font-weight-semibold` | 600 | 小标题、金额整数 |
| `font-weight-bold` | 700 | 仅展示型数字 |

迁移是**破坏性改名**（现 `medium`=600 要变 500），须走 ADR + 别名过渡期：
先新增 `--wot-font-weight-500`，把 6 处字面量 500 指过去，再统一切换 `medium` 的值。

## 5. 圆角

圆角必须**随控件尺寸走**，不能全局一个值。

| 控件尺度 | 圆角 | 令牌 |
| --- | --- | --- |
| ≤ 32px（标签、徽标、小按钮） | 4–6 | `radius-main` |
| 36–48px（按钮、输入、键盘键） | 8 | `radius-large` |
| 卡片、列表块 | 12 | `radius-extra-large` |
| 弹层、面板（顶部圆角） | 16–20 | `radius-super-large` |
| 头像、圆点、胶囊 | 9999 | `radius-full` |

现状问题：`radius-main`=4 被当作全局默认，导致 114×48 的键盘键也是 4px 圆角——
按键看起来像表格单元格。**大尺寸控件用 4px 圆角是本次体检里最普遍的观感问题。**

## 6. 层级（替代"阴影"）

Lynx 各端 `box-shadow` 表现不一致，规范**不以阴影表达层级**。

| 层级 | 表达方式 | 典型组件 |
| --- | --- | --- |
| L0 页面底 | `filled-bottom` (#F7F8FA) | 页面背景 |
| L1 内容面 | `filled-oppo` (#FFFFFF) + `border-main` 描边 | 卡片、列表、cell |
| L2 浮起 | L1 + `border-strong` 描边 | 下拉、气泡、浮层 |
| L3 模态 | 遮罩 `opacfilled-main-cover` + 白色面 | 弹窗、动作面板 |

阴影仅作为 L2/L3 的**可选增强**：必须定义成 `--wot-elevation-1/2/3` 令牌，
且**删掉阴影后层级仍成立**。现状是同一套三层阴影在 tooltip / tooltip-arrow /
popover / popover-arrow / notify 五处逐字复制——要改一次得改五处，且没有 token 名可引用。

## 7. 动效

现状：0.1 / 0.15 / 0.2 / 0.3 / 0.4s 五种时长，ease / ease-in / ease-in-out / cubic-bezier 四种缓动，
外加 9 处 `transition: all`。

**规范：三档时长 + 两种曲线。**

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `motion-fast` | 120ms | 按压反馈、颜色切换 |
| `motion-base` | 200ms | 展开收起、透明度 |
| `motion-slow` | 300ms | 位移、面板进出 |
| `easing-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | 默认 |
| `easing-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 退出 |

- **禁止 `transition: all`**：会连带动画 `width/height`，是掉帧主因。必须列属性名。
- 按压反馈用 120ms，不要用 300ms——触摸反馈超过 150ms 就会被感知为"卡"。

## 8. 色彩与对比度

色彩令牌化已经做得很好（硬编码颜色 **0 处**）。问题在**对比度**，不在令牌纪律。

| 组合 | 实测 | AA 要求 | 结论 |
| --- | --- | --- | --- |
| text-main / 白 | 14.29:1 | 4.5 | ✅ |
| text-secondary / 白 | **4.90:1** | 4.5 | ✅ 已修（原 #979797 = 2.92:1） |
| text-secondary / 填充面 #F2F3F5 | 4.42:1 | 4.5 | ⚠️ 差 0.08，填充面上不要放次文字 |
| text-auxiliary / 白 | **3.43:1** | 4.5 | ❌ 仅 ≥18px 可用 |
| text-placeholder / 白 | **2.26:1** | 4.5 | ⚠️ 占位符允许，但不得是唯一提示 |
| 白字 / primary-6 | 4.35:1 | 4.5 | ⚠️ 临界，按钮文字建议用 primary-7 |
| 白字 / success-main | **2.55:1** | 4.5 | ❌ 待决策（改底色或改深色字） |
| 白字 / warning-main | **2.65:1** | 4.5 | ❌ 待决策 |
| 白字 / danger-main | **3.68:1** | 4.5 | ❌ 待决策 |

**规范：**

1. **正文/标签文字只能用 `text-main`**。`text-secondary` 只能用于 ≥16px 的次要信息，
   且不得承载用户必须读到的内容（金额、状态、错误提示）。
2. 占位符允许低对比（这是它的语义），但 **placeholder 不得是唯一提示**——
   必须有 label。
3. **彩色底上的白字，只允许 `primary-7` 及以上档位**。`success-6` / `warning-6` 上的白字
   必须改成深色字（`text-main`），或把底色降到 -7/-8。
4. 禁用态用 `opacity-disabled`(0.4) 统一，不要写 0.5 / 0.6。

## 9. 组件契约（每个组件必须满足）

新增或修改组件时逐条自检，`design-audit` 覆盖 1–5、7：

| # | 契约 | 校验 |
| --- | --- | --- |
| 1 | 所有颜色/尺寸/圆角/字重/动效走令牌，无字面量 | D002–D008 |
| 2 | 引用的 `--wot-*` 必须已声明（含回退链全部可解析） | D001 |
| 3 | 命中区 ≥ 44px（视觉高度可小于 44） | D011 |
| 4 | 文字对比度达 AA | D012 |
| 5 | 禁用态统一 `opacity-disabled` | D010 |
| 6 | 四态齐全：默认 / 按压 / 禁用 / 焦点 | 人工 |
| 7 | 无 `transition: all`，时长取三档之一 | D008 / D009 |
| 8 | 层级在去掉阴影后仍成立 | 人工 |

### 9.1 组件级令牌的写法

```scss
// ✅ 令牌 → 语义 → 刻度，三层可解析
$keyboard-key-height: var(--wot-keyboard-key-height, $size-2xl) !default;

// ❌ 回退链指向不存在的令牌 → 整条声明失效
border-bottom: 1px solid var(--wot-border-color, var(--wot-n-200));
```

第二条是本次体检发现的**最严重缺陷类型**：`--wot-border-color` 与 `--wot-n-200` 都未声明，
`var()` 回退链全空 → 声明在计算值阶段失效 → `border-style` 回退 `none` → **分割线整条不渲染**。
共 4 处（address-edit ×2、share-sheet ×1、submit-bar ×1）。

## 10. 键盘类组件专项规范

键盘是「一屏内高密度小目标」的极端场景，不能套用普通控件的尺寸规则。

### 10.1 网格

| 模式 | 列数 | 键宽(375 屏) | 键高 | 宽高比 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 数字键盘 | 3 | 114.3 | 48 | 2.38:1 | 可用；圆角须 8（原 4 偏方） |
| 车牌（省简称 / 英数） | 10 | 28.7 | 48 | 0.60:1 | 可用，但已到下限 |

**规范：**

- **键盘是 44pt 规则的明确例外**。iOS 系统键盘单键约 31.5×42，28.7×48 与之同量级；
  键盘的「密集已知目标 + 拇指大面积接触」特性决定了它不适用普通控件的命中区标准。
- 例外的前提是三条**同时**满足，缺一条就要减列：
  1. 目标是**有限已知集合**（36 个省份、34 个字母数字），不是开放式列表；
  2. 键高 ≥ 44 作为补偿（纵向容错）；
  3. 键间距 ≥ 6，避免误触邻键。
- **列数上限 10**（再密就跌破 28px，进入不可用区）。
- 网格必须显式 `min-width: 0`：flex 项默认 `min-width: auto` 取 min-content，
  十列网格会塌成三列（2026-10-23 实测确认，见体检报告 §1.7）。
- 键宽必须**逐行一致**。末行不满时用 `flex-grow: 0` 留白，不要拉宽末行键——
  同一块键盘出现两种键宽会破坏扫描与肌肉记忆。
- 键间距统一 8（wrapper 右/下各 8，行距=列距=8，正确）。

### 10.2 数字键盘

- 键尺寸 114×48、圆角 **8**（原 4，比例上等于 28.7 宽的键用 1px，像表格单元格）。
- 字号 24 / 行高 32（现状 34，比例 1.42 偏高）。
- 删除键图标尺寸必须走 `$keyboard-key-icon-size` 令牌——
  现状模板里写死 `size="22px"`，主题改不动。
- 标题字重必须走令牌——现状 `font-weight: normal`。
- 无 `extraKey` 时显示键盘图标，但 `handlePress` 对空文本执行的是**关闭**：
  空字符串被当作"收起"，与图标语义（切换键盘）冲突。应显式区分 `type`。

### 10.3 车牌键盘

- **英数模式末行只占 8 格**：34 键按 10 列切成 30+4，第四行为
  `省份(2格) + 4键 + 删除(2格) = 8格`，尾留 2 格（73.4px）。
  省简称模式是 `2+6+2=10` 刚好填满，所以只有切到英数时才暴露。
  **正确做法是留白而不是拉宽**：`flex-grow: 0` + 尾留空，
  让两种模式的所有键宽都保持 28.7。
- **省份键与字母键同字号（18px）**：省份是单字、字母是单字母，视觉重量不同，应分别为 18 / 16。
- **切换键文案随模式变化（ABC / 省份）但宽度不变**：`省份` 两字 18px ≈ 36px，
  在 65.4px 键宽内可容；若后续加"更多"类文案会溢出，建议改为图标。
- **`__car-keys { flex: 10 }` 是死样式**：车牌模式没有 sidebar，flex 比例无参照系。
- **修饰符命名不一致**：`.wd-key.is-car` 与 BEM `wd-key--car` 混用，审计脚本按 BEM 找会漏。
- **无输入位反馈**：车牌输入框与键盘无联动视觉（当前可输入位 / 已填位数），
  这是车牌录入体验的核心反馈，缺失会让用户反复试错。

### 10.4 状态

键盘键四态：默认 `filled-oppo` / 按压 `filled-strong` / 禁用 `opacity-disabled` /
主行动键 `primary-6`（按压 `primary-7`）。现状缺**禁用态**与**按压过渡**
（背景色突变，无 120ms 过渡，触摸反馈偏硬）。

## 11. 治理

### 11.1 每次改样式

```bash
node scripts/design-audit.mjs            # 看本次引入的问题（* 标记为新增）
node scripts/review-lint.mjs             # 看平台约束
```

`design-audit --strict` 在 CI 里作为**新增缺陷门禁**：存量问题冻结在
`docs/design/audit-baseline.json`（97 条指纹，覆盖当前 142 条问题），
只对新增报错。修好一处后跑 `--update-baseline` 重签，基线只减不增。

### 11.2 新增令牌的门槛

令牌不是"给这个值起个名"，而是"这个值会被第二个组件复用"。三条同时满足才加：

1. 至少 2 个组件需要；
2. 需要被主题覆盖；
3. 落在已有阶梯上（否则先改阶梯，写 ADR）。

### 11.3 与 ADR 的关系

本文的**度量决策**（尺寸阶梯、字阶修正、字重改名、层级不用阴影）属于架构决策，
落地前需补 ADR；**用法规则**（什么时候用哪个令牌）属于本文，直接生效。
