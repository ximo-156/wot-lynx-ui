02最贵的一个缺陷：分割线整条不渲染

border-bottom: 1px solid var(--wot-border-color, var(--wot-n-200)) —— 两个名字都不存在。 根因不在组件，在语义层：--wot-border-color 只在 high-contrast 预设里被覆盖过， 基础 light/dark 从未声明。回退链全空 → 声明在计算值阶段失效 → border-style 回退 none。

03键盘：真实缺陷比原报告判断的更严重

原报告按 CSS 数学推导，说车牌键盘是「10 列 / 末行空 20%」。实测后两个判断都要更正： 修复前它根本没排出 10 列，而是塌成了 3 列——每行 3 个键、键宽 122.3px。 根因是 .wd-key-wrapper { flex: 1 } 带来的 min-width: auto （flex 项下限取 min-content = 92.7px）。

10 / 10 / 10 / 8 行✓ 高 232px

单键 28.7 不算不可用：iOS 系统键盘单键约 31.5×42，同一量级。 键盘是「密集已知目标 + 键高补偿」的成体系例外，所以撤回「10 列改 5 列」的结论—— 改 5 列会让 36 个省份变 8 行或需分页，还破坏与 wot-ui 的度量对齐。

改了什么

min-width: 0 解除 min-content 下限；flex: 1 → flex: 0 1 auto 让末行不满时留白而不是把键拉宽（否则英数末行键会变 40.9，同一块键盘出现两种键宽）。 数字键圆角 4 → 8，车牌键单独保持 4（新增 --wot-keyboard-key-car-radius）。

顺带清掉的令牌旁路

删除键图标 size="22px" 写死在模板里 → 改由 --wot-keyboard-key-icon-size 下发；标题 font-weight: normal → 令牌； background-color: transparent → $filled-zero； __car-keys { flex: 10 } 死样式 → flex: 1。

实测数据（headless Chrome，375 视口，加载真实 index.css）： 修复后省简称 10/10/10/8 行、英数 10/10/10/6 行，键宽恒为 28.7（wider 65.4）， 数字键圆角 8px、车牌键 4px。

05为什么剩下 12 个不修

因为它们不是「写错了」，而是「要改产品」。

P0触控目标 < 44px（6 处）

默认按钮 40、搜索框 36、步进器 28、胶囊 32。正确修法是「视觉高度不变、命中区外扩到 44」， 但 Lynx 无伪元素，外扩必须加一层容器——属于结构改动，会动既有布局与视觉基线。 默认按钮 40 → 44 则是密度决策，得先定「一屏放几个」。

P0语义色上的白字（5 组）

success 2.55、warning 2.65、danger 3.68、primary 4.35。改的都是品牌语义色本身—— 底色一变，全库按钮、标签、进度条一起变。不是修 bug，是改品牌。
